A small experiment

Tagging for Correct Aggregation

One model answered the same restaurant-finance questions in four setups. This page replays the recorded runs. It does not call a model.

Tag: a rule attached to a metric, kept in tags/tags.yaml. For example, the total_assets tag sets additive_over_time: false, time_rollup: last and reads: “Balance at the period end; the yearly value is the balance at the last quarter end.” In plain terms: a balance; never sum it across quarters.

Terms used on this page
Setups
A sees only the table schema. B gets prose sentences generated from the tags. C gets the tags file itself. D gets semantic tools that apply the tags, and no SQL.
Expected behaviour
Each question's answer key expects one of three: answer (34 questions), answer with warning (4 questions), refuse (4 questions).
FINAL line
Every run ends with a FINAL line: the number, its unit and two flags. warning=true means the model attached a caveat to its number; refused=true means it declined to give a number.
Stored trap
A specific wrong answer computed in advance for a question, such as the sum of four quarter-end balances. A run hits the trap when its number lands within tolerance of it.
Correct
The run's behaviour matches the key and, unless the key expects a refusal, its number is within a per-unit tolerance defined in eval/score.py.
The problem

SQL can run correctly and answer the wrong question.

Total assets is a balance at a point in time. Summing quarter-end balances produces a valid SQL result, but not annual total assets.

Filing dates in the replays. The dataset rule, from the tags' lineage and the SPEC decisions log: “Duration facts keep the latest-filed row; balance-sheet facts keep the earliest-filed row, because later filings can mis-date comparatives.” So a stored prior-year figure for revenue, income or cash flow can carry the accession number and filing date of a later filing that repeated it as a comparative. This is by design. Replay text in which a model remarks on odd filing dates is describing that rule, not corrupt data.
